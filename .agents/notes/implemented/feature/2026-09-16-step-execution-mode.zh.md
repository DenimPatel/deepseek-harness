# Agent Note: 基于两个已有文档暂停点的单步执行模式

Status: implemented

[English](2026-09-16-step-execution-mode.md) | 中文

## 问题

模型很快，agent loop 因此难以跟随。Web 可观测面板的 Flow 视图已经实时渲染每一轮、每一步、每个请求与每次工具调用，但读者找到解释刚才发生了什么的那一行时，循环又已经跑了好几步。要跟随循环，就需要能在选定位置把它停下、查看状态、再逐个单元继续——这是调试器提供的交互，而不是更慢的模型或更丰富的日志。

循环没有暂停。`AgentStatus` 只有 `idle | running`，唯一的停止方式是 `agent.cancel()`，而取消是中止该轮而非将其挂起。把 suspend/resume 状态机加进循环，就得重新回答现有取消、收件箱领取与驱动器收敛规则已经回答过的每个问题。

## 决策

单步模式停在循环与工具注册表已经文档化的两个扩展点上，因此这两个包都不需要改动。`agent/pre-step` 在该步领取收件箱输入并完成请求组装之后、`step/start` 之前运行，也就是“上下文已就绪、尚未发出请求”。`tools/pre-execute` 在派发之前、该调用的审批询问之前运行，因此被拦下的调用会先于任何权限提示做出决定；`run_code` 子调用走同一阶段。`@deepseek-ai/dsh-step-mode`（`packages/interaction/step-mode`）各注册一个监听器，通过等待 waterfall 应答来拦下一步。

应答走产品已经在用的人工交互路径。`step-mode/advance` 是 Agent 作用域的转发 waterfall（`packages/api/remotes/src/remote-events.ts`），在浏览器中由 `ctx.remote.$on` 应答、发布为 Session 待处理交互，并由 `@deepseek-ai/dsh-client-ui-step-mode`（`packages/client/ui-step-mode`）渲染。应答为 `{ action: 'step' }` 表示只运行这一个单元，`{ action: 'resume' }` 表示不再暂停地运行完本次运行。

武装按每次运行一次性生效，且位于主机侧，因此未武装的运行不付出任何往返。输入框的 `Alt+Enter` 手势与输入框工具行的单步按钮都通过 Session 已有的命令动词执行 `/step`，然后发送草稿；`ui-conversation` 通过 `ctx.get('stepMode')` 读取武装能力并拥有该手势，因此两个包都不导入对方的运行时值。接管卡片替换输入框时 `Shift+Enter` 推进一步，而在输入草稿时它仍是换行。

两个失败方向是刻意相反的。暂停**放行**：没有应答者、分发被拒绝（例如浏览器断开）、监听器抛错、以及轮次被取消，都会继续，因此无人值守的运行永远不会挂起，且只有运行时根 Agent 会被拦下。武装**失败即拒绝**：武装被拒绝时显示失败并不发送任何内容，因此 `Alt+Enter` 不会悄悄开始一次普通运行。

## Consequences

`agent/pre-step` 在 `inbox.claim()` 之后运行，因此在第一步暂停期间取消，会在不重新发出已领取消息的情况下结束该轮——与任何在领取之后被取消的轮次结果相同，并被记录为限制而不是被掩盖。重新加载会丢失待处理的暂停，因为主机不会向新的浏览器世代重新宣告暂停。两者都不是循环改动，而是所选扩展点的代价。

## 考虑过的替代方案

**在 agent loop 中增加 suspend/resume 阶段。** 否决：它会为一个调试器功能重复驱动器已有的收敛、取消与收件箱规则，而 `docs/architecture.md` 已经用 `agent/*` 与 `tools/*` 事件回答了“拦截请求、工具或轮次”。

**每一步都询问浏览器，由它决定是否暂停。** 否决：这会在每次运行的每个模型请求与每次工具调用之前都加入一次网络往返，包括未开启单步模式的运行。

**在领取之前暂停，使取消暂停不会丢失输入。** 目前否决，因为没有文档化的扩展点在 `inbox.claim()` 之前运行；提供这样一个扩展点属于循环改动，而其当前唯一消费者就是本功能。

**把武装持久化到设置中。** 否决：粘性模式会在用户未武装的情况下悄悄对之后的运行逐步暂停。武装属于一次运行，并由继续运行的决策、运行进入 `idle`，或 `/step off` 释放。

**在 `SessionPromptRequest` 上增加 `step` 字段。** 否决：这会让通用 Session 传输感知一个调试器功能。命令注册表已经能在不新增传输类型的情况下，把用户手势送达主机插件。
